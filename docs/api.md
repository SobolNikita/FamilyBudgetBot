# HTTP API

[← README](../README.md)

Панель и API не требуют авторизации по ТЗ и дают доступ ко всей семье. Базовый адрес при локальном запуске — http://localhost:8080. Не публикуйте его в открытый интернет без отдельной защиты доступа.

## Расходы и служебные маршруты

| Метод  | Путь                            | Назначение                                                                      |
| ------ | ------------------------------- | ------------------------------------------------------------------------------- |
| GET    | `/api/config`                   | Валюта, часовой пояс, текущая дата семьи                                        |
| GET    | `/api/categories`               | Категории                                                                       |
| GET    | `/api/expenses`                 | Расходы: `user_id`, `from`, `to`, `category`, `search`, `limit`, `offset`       |
| GET    | `/api/expenses/{id}`            | Получить актуальную запись для разрешения конфликта веб-формы                   |
| POST   | `/api/expenses`                 | Создать расход                                                                  |
| PUT    | `/api/expenses/{id}`            | Заменить поля расхода с проверкой `version`                                     |
| DELETE | `/api/expenses/{id}?version=1`  | Удалить расход с проверкой версии                                               |
| GET    | `/api/reports/summary`          | Точная сумма и категории с теми же фильтрами                                    |
| GET    | `/health/live`, `/health/ready` | Работа процесса и доступность PostgreSQL                                        |
| GET    | `/health/bot`                   | Состояние polling/worker/LLM; 503 при деградации, отдельно от readiness веба    |
| GET    | `/health/queues`                | Размеры и возраст очередей, приостановленная доставка и статистика HTTP-пула БД |

Для `POST /api/expenses` обязателен заголовок `Idempotency-Key`: случайный идентификатор операции из 16–128 букв, цифр, `-` или `_`. При повторе после обрыва связи используйте тот же ключ и те же поля: сервер вернёт исходный результат, даже если расход уже изменён или удалён, и не создаст новую запись. Другие данные с тем же ключом дают 409. Новая намеренная покупка должна иметь новый ключ. Записи ключей сохраняются без автоматического истечения; удаление таблицы `expense_requests` отменяет защиту старых повторов.

Пример тела создания:

```json
{
  "user_id": "123456789",
  "amount": "12.50",
  "category": "еда",
  "spent_at": "2026-10-16",
  "comment": "Кофе"
}
```

ID и суммы в API — строки, чтобы не терять точность JavaScript. При обновлении также передаётся текущая `version`; при конфликте сервер возвращает `409`, при неверных данных — `400`, при отсутствии записи — `404`. Границы периода включительны, размер страницы — до 100 записей. Отчёт считает весь выбранный период независимо от пагинации.

Повтор создания с ключом, отозванным при удалении участника, возвращает 410; сохранённый ответ с личными данными очищен.

## Участники

| Метод  | Путь                                | Назначение                                                       |
| ------ | ----------------------------------- | ---------------------------------------------------------------- |
| GET    | `/api/users`                        | Зарегистрированные активные участники с `version`                |
| GET    | `/api/users/removed`                | Telegram ID, версия и дата удаления; без имени                   |
| DELETE | `/api/users/{id}?version=N`         | Удалить участника и его данные; повтор той же операции безопасен |
| POST   | `/api/users/{id}/restore?version=N` | Разрешить регистрацию заново; данные не восстанавливает          |

Удаление очищает расходы и данные участника, восстановление разрешает новое знакомство с ботом. Версия в этих маршрутах относится к членству, а не к расходу. Подробности — в [руководстве](usage.md#удаление-и-восстановление-участника).

## Массовое удаление

API: `GET /api/expenses/selection` принимает те же фильтры, что список, и возвращает `{ "token": "…", "count": 45 }`. `POST /api/expenses/bulk-delete` с теми же query-фильтрами и JSON `{ "token": "…" }` возвращает `{ "deleted": 45 }`. Параметры `limit` и `offset` не ограничивают выбор. Токен — условие согласованности, а не средство авторизации. Проверка набора и удаление используют исключительную блокировку жизненного цикла, совместимую с обычными записями и удалением участников; операция ограничена общим таймаутом БД.

Для исключений передайте `{ "token": "…", "exclude": ["42"] }`; для ручного выбора — `{ "items": [{ "id": "42", "version": 1 }] }` без токена. ID передаются строками. Режимы нельзя смешивать; повторяющиеся ID запрещены. Каждый ID должен принадлежать текущему фильтру. Допускается до 1000 отдельных записей или исключений; полный выбор по токену не ограничен этим числом. Тело запроса ограничено 128 КиБ.

Если выбранные записи или их версии изменились, сервер возвращает 409 без частичного удаления. После конфликта обновите список и сформируйте новый выбор. [Работа с чекбоксами](usage.md#массовое-удаление-расходов).
