# 0.4.0 — выбор отдельных расходов

## Изменения

- Рядом с крестиком каждого расхода появился чекбокс. Отмеченные строки подсвечиваются; «Удалить выбранное» показывает число записей и открывает подтверждение.
- Выбор сохраняется между страницами. После выбора всего фильтра можно снять галочки с отдельных расходов — они останутся в базе.
- Обновлено оформление общего выбора: закруглённый чекбокс, блок с подписью, счётчик, команда «Снять выбор». Поддерживаются пустое, частичное и полное состояния, клавиатура, мобильная вёрстка и обе темы.
- Ручной выбор хранит исходные ID/версии. Сервер проверяет каждую запись и её соответствие фильтру; при конфликте откатывается вся операция. Изменения невыбранных записей не препятствуют ручному удалению.
- Выбор всего фильтра сохраняет прежнюю проверку отпечатка полного набора, дополненную исключениями. Повторные и неизвестные ID отклоняются. Потеря ответа не запускает автоматический повтор удаления.

## API и обновление

`POST /api/expenses/bulk-delete` принимает один из вариантов:

- `{ "items": [{ "id": "42", "version": 1 }] }` — ручной выбор.
- `{ "token": "…", "exclude": ["42"] }` — весь фильтр без перечисленных ID.

Прежний запрос только с `token` совместим. Фильтры передаются в query. Лимит — 1000 отдельных записей или исключений и 128 КиБ на тело; полный выбор по токену не ограничен этим числом. Подробности — в README.

Новых миграций и зависимостей нет. Обновление: `docker compose up --build -d`, затем обновить страницу. При переключении версии сначала остановите прежний экземпляр приложения, чтобы одновременно не работали два Telegram-поллера. Перед обновлением сохраните копию базы.

## Проверки

- Go-тесты с изолированной PostgreSQL и race detector; go vet, HTTP-тесты и форматирование.
- Точное удаление отмеченных версий, сохранение неотмеченных записей, конфликт при изменении/удалении/переносе выбранной записи и при ID вне фильтра; отсутствие частичного удаления.
- Выбор 45 записей с сохранением двух исключений; валидация смешанных режимов, повторяющихся и неверных ID, лимитов.
- TypeScript/Vite, ESLint, Prettier, 20 тестов фронтенда.
- Браузер: выбор строк на разных страницах, управление пробелом, частичное состояние, исключения, отмена и точный состав запросов удаления. Проверено оформление на 320 и 1440 px в светлой и тёмной темах; прежние проверки 320–1440 px также проходят.
- Изолированный Compose: действительные HTTP-запросы выбора с исключениями, ручного удаления, конфликта и повторов.

Разрушающие проверки выполнялись только в тестовых базах. Внешние Telegram/LLM end-to-end не запускались.
