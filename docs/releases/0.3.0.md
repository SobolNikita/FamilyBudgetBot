# 0.3.0 — массовое удаление расходов

## Изменения

- В окне участников и остальных модальных окнах крестик заменён на SVG. Кнопка 44×44 px не сжимается, иконка выровнена по центру.
- Над расходами появился выбор всех записей по текущему фильтру, включая остальные страницы. Повторное нажатие снимает выбор; смена фильтра или обновление списка сбрасывают его. Переход между страницами сохраняет выбор.
- Подтверждение показывает число расходов, участника, категорию и период. Удаление выполняется одной транзакцией. При изменении выбранного набора возвращается 409 без частичного удаления; новые записи не попадают под повтор старого запроса.
- При потере ответа интерфейс предлагает обновить список и повторно выбрать расходы. Автоматического повтора удаления нет.
- Итоги пересчитываются, список возвращается на первую страницу. Механизмы ревизии расходов и обновления контекста бота продолжают работать; участники не удаляются.

## API и обновление

`GET /api/expenses/selection` возвращает число записей и отпечаток набора ID/версий для переданных фильтров. `POST /api/expenses/bulk-delete` принимает те же фильтры и тело `{ "token": "…" }`. `limit` и `offset` не ограничивают выбор. Подробности — в README.

Новых миграций и зависимостей нет. После получения релиза выполните `docker compose up --build -d` и обновите страницу. При обновлении остановите предыдущий экземпляр приложения до запуска нового, чтобы не запускать двух Telegram-поллеров одновременно. Резервная копия данных перед обновлением рекомендуется.

## Проверки

- Go-тесты с отдельной PostgreSQL и race detector; go vet и форматирование.
- Удаление 45 записей с нескольких страниц; сохранение записей вне фильтра по участнику, категории, обеим датам и поиску.
- Конфликты при добавлении, изменении, переносе и удалении записей; ожидание конкурирующей транзакции, таймаут без частичного удаления, безопасный повтор старого запроса.
- HTTP-маршруты, валидация фильтров и тела, передача условия согласованности, код 409.
- TypeScript/Vite, ESLint, Prettier и 18 тестов фронтенда.
- Браузер: 400 выбранных записей при 20 строках на странице, переход страниц, сброс при смене фильтра, отмена, успешное удаление, конфликт, потеря ответа, отсутствие повторной записи. Геометрия крестика на 320 и 1440 px, отсутствие горизонтальной прокрутки панели выбора на 320 px.
- Изолированный Compose: сборка, запуск, действительные HTTP-запросы массового удаления, конфликт, повтор и сохранение другого участника.

Рабочая база не использовалась для разрушающих тестов. Внешние Telegram/LLM end-to-end не запускались.
